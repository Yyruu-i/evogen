## 一、各模块详细功能定义与接口契约

### 1.1 通道网关（Channel Gateway）

#### 1.1.1 模块职责

通道网关是 EvoGen 的统一入口，负责所有外部通信的管理——包括客户端连接、消息平台接入、身份认证和协议适配。

#### 1.1.2 子模块定义

##### A. WebSocket 协议服务（WS Protocol Server）

| 属性 | 内容 |
|------|------|
| **功能** | 提供基于 WebSocket + JSON 的双向通信协议 |
| **端口** | 默认 18789，可配置 |
| **传输格式** | JSON text frames，首帧必须为 `connect` |

**接口契约——帧类型定义：**

```
帧类型枚举：
  CONNECT_REQUEST   = {type: "req", method: "connect", params: {...}}
  CONNECT_RESPONSE  = {type: "res", id: string, ok: bool, payload: {...}}
  AGENT_REQUEST     = {type: "req", method: "agent", params: {message, session?, thinking?, ...}}
  AGENT_RESPONSE    = {type: "res", id: string, ok: bool, payload: {runId, status, summary?}}
  AGENT_EVENT       = {type: "event", event: "agent", payload: {runId, chunk, ...}}
  HEALTH_REQUEST    = {type: "req", method: "health"}
  HEALTH_RESPONSE   = {type: "res", ok: bool, payload: {uptime, sessions, ...}}
  PRESENCE_EVENT    = {type: "event", event: "presence", payload: {status, ...}}

CONNECT 请求参数：
  {
    deviceId: string,        // 设备唯一标识
    deviceName: string,      // 设备显示名
    platform: string,        // 客户端平台 (cli/web/ios/android)
    auth: {
      token?: string,        // 已配对设备Token
      password?: string,     // Gatewa密码认证
    },
    role: "client" | "node",  // 客户端角色
    caps?: string[],          // 能力声明 (仅 node)
  }
```

### 1.3 Agent 层（Agent Core）

#### 1.3.1 Agent 主循环（Agent Loop）

```
接口：AgentLoop

  伪代码逻辑：
    async def run(session: Session, user_message: Message) -> Response:
        # 1. 从进化记忆引擎加载记忆快照
        memory_snapshot = await memory_engine.get_snapshot(session)
        
        # 2. 从人格引擎获取当前行为策略
        persona = await persona_engine.get_active_persona(session)
        
        # 3. 从技能引擎匹配适用技能
        skills = await skill_engine.match_skills(user_message, session)
        
        # 4. 组装上下文
        context = await context_engine.build_context(
            session, memory_snapshot, persona, skills
        )
        
        # 5. 开始主循环
        iteration = 0
        trajectory = []  # 执行轨迹（用于经验学习）
        while iteration < max_iterations:
            # 5a. 检查是否需要压缩
            if context_engine.estimate_tokens(context) > threshold:
                context = await context_engine.compress(context)
            
            # 5b. 选择模型并调用LLM
            model = await model_router.select(context, budget)
            response = await llm_call(model, context)
            
            # 5c. 如果有tool_calls，分发执行
            if response.tool_calls:
                results = await toolchain_manager.dispatch(response.tool_calls)
                trajectory.append({"turn": iteration, "calls": results})
                context.append(results)
                continue
            
            # 5d. 文本响应，结束循环
            break
        
        # 6. 记录任务执行轨迹，提交经验学习引擎（异步）
        await experience_engine.submit_trajectory(
            session, trajectory, response
        )
        
        # 7. 从本次交互中提取记忆事实（异步）
        await memory_engine.extract_and_store(
            session, user_message, response, trajectory
        )
        
        return response
```

#### 1.3.2 任务编排器（Task Orchestrator）

```
接口：TaskOrchestrator

  方法：
    async analyze_complexity(task: Task) -> ComplexityReport
      # 分析任务复杂度，决定是否需要拆解
      # 评估维度：预估步骤数、依赖复杂度、领域多样性、时间跨度

    async decompose(task: Task) -> TaskDAG
      # 将任务拆解为子任务的依赖图（DAG）
      # 算法：
      #   1. 要求LLM输出任务树（结构化JSON）
      #   2. 识别子任务间的依赖关系
      #   3. 标记可并行的子任务组
      #   4. 构建DAG

    async spawn_subagent(subtask: SubTask, parent_memory: MemorySnapshot) -> SubAgentHandle
      # 启动子Agent
      # 子Agent继承父Agent的记忆快照（过滤后）
      # 返回Agent句柄用于查询状态和获取结果

    async merge_results(results: List[SubAgentResult]) -> MergedResult
      # 合并多个子Agent的结果
      # 逻辑：
      #   1. 按依赖图拓扑排序
      #   2. 识别冲突（如两个子Agent修改了同一文件）
      #   3. 自动消解或标记需人工处理

  数据结构：
    TaskDAG:
      nodes: List[TaskNode]
      edges: List[(TaskNode, TaskNode)]  # from → to，表示依赖
      max_parallelism: int

    ComplexityReport:
      score: float                # 0-1，复杂度评分
      recommended_strategy: "direct" | "sequential" | "parallel" | "hierarchical"
      estimated_turns: int
      confidence: float
```

### 1.4 进化层——核心差异化

#### 1.4.1 进化记忆引擎（Evolutionary Memory Engine）

这是 EvoGen 最核心的差异化模块。

```
接口：EvolutionaryMemoryEngine

  ┌─────────────────────────────────────────────────────┐
  │                  记忆引擎架构                          │
  │                                                      │
  │   ┌──────────┐    ┌──────────┐    ┌──────────┐     │
  │   │ 瞬态记忆  │ →  │ 工作记忆  │ →  │ 核心记忆  │     │
  │   │ (会话内)  │    │ (跨会话) │    │ (永久)   │     │
  │   │ TTL: 会话 │    │ TTL: 衰减 │    │ TTL: ∞   │     │
  │   └──────────┘    └──────────┘    └──────────┘     │
  │        ↑               ↑               ↑            │
  │        │   自动提取     │   强化/衰减   │            │
  │        └───────────────┴───────────────┘            │
  │                    记忆管理器                         │
  │          · 事实提取 · 关系识别 · 衰减调度             │
  │          · 冲突解决 · 合并去重 · 隐私过滤             │
  └─────────────────────────────────────────────────────┘

方法：
  async extract_and_store(
    session: Session,
    user_message: Message,
    assistant_response: Message,
    trajectory: TaskTrajectory
  ) -> List[MemoryFact]
    # 从交互中自动提取记忆事实
    # 算法流程：
    #   1. 对用户消息和助手回复做事实提取（LLM zero-shot）
    #   2. 实体识别 + 关系抽取 → 更新知识图谱
    #   3. 对提取到的事实进行重要性评分
    #   4. 高频事实 → 强化（提升记忆权重）
    #   5. 关键事实 → 存入工作记忆
    #   6. 冲突事实 → 标记并提示用户确认

  async get_snapshot(session: Session) -> MemorySnapshot
    # 获取当前会话的完整记忆快照
    # 快照包含：
    #   - 核心记忆（全量）
    #   - 工作记忆中相关性 > 阈值的条目
    #   - 瞬态记忆（全部）
    # 相关性计算：用户消息 embedding × 记忆条目 embedding

  async reinforce(fact_id: str, amount: float) -> None
    # 强化记忆（增加权重，延长衰减周期）

  async decay_schedule() -> None
    # 记忆衰减调度（后台定时任务）
    # 算法：艾宾浩斯遗忘曲线变体
    #   weight(t) = initial_weight × e^(-decay_rate × t / importance)
    #   其中 importance 随 reinforce() 增加
    #   当 weight < 阈值 → 降级到下一层
    #   当在最低层且 weight < 最低阈值 → 归档（不删除）

  async search_memories(query: str, top_k: int) -> List[MemoryFact]
    # 向量语义搜索记忆

  async query_knowledge_graph(entity: str, relation?: str) -> List[GraphTriple]
    # 查询知识图谱中的实体和关系

  async detect_contradiction(fact: MemoryFact) -> List[MemoryFact]
    # 检测新事实是否与已有记忆矛盾

数据结构：
  MemoryFact:
    id: str
    type: "preference" | "fact" | "procedure" | "relationship"
    content: str                   # 记忆内容
    embedding: List[float]         # 向量嵌入
    importance: float              # 重要性评分 (0-1)
    weight: float                  # 当前权重（衰减中）
    decay_rate: float              # 衰减速率（随强化降低）
    source_interaction: str        # 来源交互ID
    created_at: datetime
    last_reinforced_at: datetime
    layer: "transient" | "working" | "core"
    confidence: float              # Agent 对该事实的确信度 (0-1)
    contradictions: List[str]      # 冲突的事实ID列表
    privacy_level: "public" | "private" | "sensitive"

  MemorySnapshot:
    core_facts: List[MemoryFact]
    working_facts: List[MemoryFact]
    transient_facts: List[MemoryFact]
    relevant_graph_triples: List[GraphTriple]
    generated_at: datetime
    snapshot_id: str
```

#### 1.4.2 经验学习引擎（Experience Learning Engine）

```
接口：ExperienceLearningEngine

  ┌─────────────────────────────────────────────────────┐
  │                经验学习引擎架构                         │
  │                                                      │
  │   任务执行 → 轨迹记录 → [异步队列] → 离线反思分析     │
  │                                         ↓            │
  │                                    策略优化建议       │
  │                                         ↓            │
  │                                   A/B 自测试          │
  │                                         ↓            │
  │                              通过 → 策略版本发布       │
  └─────────────────────────────────────────────────────┘

方法：
  async submit_trajectory(
    session: Session,
    trajectory: TaskTrajectory,
    outcome: TaskOutcome
  ) -> str
    # 提交任务执行轨迹到分析队列
    # 返回轨迹ID

  async reflect(trajectory_id: str) -> ReflectionReport
    # 对单个任务轨迹进行反思分析（后台异步）
    # 分析维度：
    #   1. 工具选择的合理性
    #   2. 任务拆解的有效性
    #   3. Token 使用效率
    #   4. 错误处理质量
    #   5. 用户满意度信号（修改/取消/重试）

  async aggregate_reflections(time_window_days: int) -> StrategyInsight
    # 聚合一段时间内的反思，发现模式
    # 产出：
    #   - 高频失败模式 → 建议更改策略
    #   - 高效工具组合 → 建议固化为工作流
    #   - Token 浪费模式 → 建议优化提示词

  async optimize_strategy(
    insight: StrategyInsight
  ) -> StrategyVariant
    # 根据聚合洞察生成优化策略变体
    # 例如：
    #   - 修改系统提示词的特定段落
    #   - 调整工具选择偏好权重
    #   - 优化任务拆解阈值

  async run_ab_test(
    baseline: StrategyVariant,
    candidate: StrategyVariant,
    test_sessions_limit: int
  ) -> ABTestResult
    # 对策略变体进行 A/B 测试
    # 在限定的会话数量中随机分配策略
    # 统计关键指标差异
    # 当置信度 > 95% 时自动采用优胜策略

  async promote_strategy(variant_id: str) -> None
    # 将验证通过的策略变体提升为默认策略

  async rollback_strategy(variant_id: str, reason: str) -> None
    # 回滚策略（当新策略表现不佳时）

数据结构：
  TaskTrajectory:
    id: str
    session_id: str
    task_description: str
    turns: List[TrajectoryTurn]
    tool_calls: List[ToolCallRecord]
    total_tokens: int
    wall_time_ms: int
    success: bool
    user_feedback_signals: List[FeedbackSignal]

  ReflectionReport:
    trajectory_id: str
    analysis: str                  # LLM生成的反思分析
    strengths: List[str]
```

### 2.2 记忆衰减算法

```
算法：AdaptiveEbbinghausDecay
  输入：所有工作记忆中的 MemoryFact
  触发：定时（每小时）或触发式（每次 extract 后）

  对每个 fact ∈ working_facts:
    # 计算当前年龄（距上次强化的小时数）
    age_hours = (now - fact.last_reinforced_at).total_hours()
    
    # 基础衰减：修正的艾宾浩斯曲线
    base_decay = exp(-decay_rate × age_hours / importance)
    
    # 衰减速率自适应：
    #   - 被频繁 recall（search/snapshot命中）→ decay_rate *= 0.95（减缓衰减）
    #   - 从未被recall → decay_rate *= 1.05（加速衰减）
    
    # 新权重
    fact.weight = initial_weight × base_decay
    
    # 层迁移决策：
    if fact.weight < working_to_core_threshold and fact.importance > 0.8:
        # 高重要性低衰减 → 提升到核心记忆
        fact.layer = "core"
        fact.decay_rate *= 0.1  # 核心记忆几乎不衰减
    elif fact.weight < working_to_archive_threshold:
        if fact.layer == "working":
            fact.layer = "archive"  # 归档（不删除，但不加载到上下文）
        elif fact.layer == "core":
            # 核心记忆降级前需要用户确认
            suggest_deletion(fact)
```

### 2.3 自动事实提取算法

```
算法：InteractionFactExtractor
  输入：用户消息 + 助手回复 + 工具调用轨迹
  输出：List[MemoryFact]

  步骤：
    1. 调用小模型（如 GPT-4o-mini 或本地模型）做信息提取：
       
       提示词模板：
       """
       从以下交互中提取用户相关的事实信息。输出格式为 JSON数组：
       [
         {
           "type": "preference|fact|procedure|relationship",
           "content": "事实内容",
           "importance": 0.0-1.0,
           "privacy_level": "public|private|sensitive",
           "entity_subject": "主体",
           "entity_object": "客体（可选）",
           "relation": "关系（可选）"
         }
       ]
       
       规则：
       - preference: 用户的偏好、习惯、倾向
       - fact: 关于用户、项目、环境的陈述性事实
       - procedure: 用户的工作流程或行为模式
       - relationship: 实体间的关系
       - importance 评分：
         0.8-1.0: 核心个人信息（姓名、角色、常用项目）
         0.5-0.8: 重要但可变化的信息（当前任务、技术选型）
         0.2-0.5: 临时或一次性信息
         0.0-0.2: 琐碎信息，可忽略
       """
    
    2. 生成 embedding（使用轻量级 embedding 模型）
    
    3. 对每个提取到的事实：
       a. 与已有记忆做语义相似度匹配（cosine similarity > 0.85）
       b. 如果高度相似 → 更新已有事实（强化权重）
       c. 如果部分相似 → 检测矛盾：
          - 用 LLM 判断新旧事实是否矛盾
          - 如果矛盾 → 标记新事实为 pending，创建冲突记录
          - 如果不矛盾 → 合并（如更新项目状态）
       d. 如果完全不相似 → 新增事实
    
    4. 实体/关系提取：
       a. 从事实中提取命名实体
       b. 从事实中提取实体间关系
       c. 更新知识图谱：upsert 节点和边
```

### 2.4 经验反思算法

```
算法：TrajectoryReflector
  输入：TaskTrajectory
  输出：ReflectionReport

  步骤：
    1. 轨迹摘要生成：
       - 压缩完整轨迹为结构化摘要
       - 突出：关键决策点、工具调用链、错误和恢复

    2. 多维度反思（每个维度用独立的 LLM 提示）：
       a. 工具选择分析：
          对比"实际使用的工具" vs "理想工具链"
          识别：冗余工具调用、缺失工具、低效组合

       b. 任务拆解分析：
          评估拆解粒度是否合理
          识别：过度拆解（over-decomposition）、欠拆解（under-decomposition）

       c. Token 效率分析：
          上下文中的冗余信息比例
          识别：可压缩的重复信息、低价值系统消息

       d. 错误处理分析：
          错误是否被正确识别和恢复
          识别：可避免的错误模式

       e. 用户满意度推断：
          从后续行为推断：继续协作 vs 修改/取消 vs 手动完成
          信号权重：继续协作(高) < 修改要求(中) < 取消(低) < 手动完成(很低)

    3. 综合评分：
       score = weighted_average([
         (tool_selection_score, 0.25),
         (decomposition_score, 0.20),
         (token_efficiency_score, 0.15),
         (error_handling_score, 0.20),
         (user_satisfaction_score, 0.20),
       ])

    4. 生成改进建议（按优先级排序）
```

### 4.2 技术选型理由

| 选择 | 理由 | 放弃的方案 |
|------|------|-----------|
| **Python 主语言** | AI/LLM 生态最成熟，技能/插件系统天然支持动态加载 | TypeScript（更适合 Web，AI 生态较弱） |
| **Rust 关键路径** | 记忆引擎的向量检索和衰减计算需要高性能 | Cython（复杂度高） |
| **LanceDB** | 嵌入式，无外部依赖，Rust 编写，性能优秀 | Chroma（需 Python 进程）、Qdrant（需额外部署） |
| **KuzuDB** | 嵌入式图数据库，支持 Cypher 语法，零运维 | Neo4j（重量级）、NetworkX（内存型） |
| **WebSocket + JSON** | 与 OpenClaw 保持一致，浏览器原生支持 | gRPC（性能好但调试复杂、Web 支持需代理） |
| **LiteLLM** | 统一 100+ 提供商接口，简化模型切换 | 直接 API 调用（维护成本高） |
| **Docker + Wasmtime** | Docker 成熟 + Wasm 启动 <1ms 适合高频小任务 | Firecracker（太重）、gVisor（性能损耗） |

## 五、关键非功能设计

### 5.1 隐私设计（Privacy by Design）

```
原则：
1. 本地优先：所有记忆和知识图谱默认存储在用户本地
2. 加密可选：支持端到端加密的云同步（用户主动开启）
3. 分级存储：
   - public: 可同步到云
   - private: 仅本地存储
   - sensitive: 加密本地存储
4. 遗忘权：用户可随时删除任意记忆，以及所有衍生信息
5. 透明度：记忆引擎提供完整的 "这段记忆来自哪里" 追踪
```

### 5.2 安全防护层次

```
Layer 1 - 网络层：DM 配对 + Token 认证 + TLS
Layer 2 - 会话层：命令审批 + 危险等级评估
Layer 3 - 执行层：Docker/Wasm 沙盒 + 资源限制
Layer 4 - 数据层：密钥不落盘 + 审计日志
```

### 5.3 性能优化策略

| 优化点 | 策略 |
|--------|------|
| **记忆检索** | 向量索引 (LanceDB IVF-PQ) + 缓存热记忆 |
| **上下文压缩** | 混合压缩：摘要 + 关键信息抽取 + 向量检索替代完整历史 |
| **LLM 调用** | Provider Pool 负载均衡 + Token 预算动态分配 |
| **并行工具调用** | 无依赖的工具调用并行执行 |
| **子Agent启动** | 预热池（进程池）减少冷启动延迟 |
