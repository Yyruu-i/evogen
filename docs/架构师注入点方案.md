```python
# ── EvoGen: 注入点 A — Agent Loop 启动前加载 ──────────────────
# 在系统提示词已组装完毕后，主循环启动前加载：
# 1. 记忆快照：从 EvoGen Memory Store 加载当前用户的全量记忆
# 2. 人格配置：加载当前用户的人格参数（tone, verbosity, persona_name 等）
# 3. 经验索引：从 Experience Store 加载与当前 query 相关的经验记录
# 这些数据存储在 agent._evogen_* 属性上，供后续注入点使用
if agent._evogen_enabled:
    from evogen.loader import EvoGenLoader
    agent._evogen_loader = EvoGenLoader(agent.session_id)
    
    # 1. 记忆快照
    agent._evogen_memory_snapshot = agent._evogen_loader.load_memory_snapshot(
        user_id=getattr(agent, "_user_id", agent.session_id),
        max_tokens=2000,  # 可配置
    )
    
    # 2. 人格配置
    agent._evogen_persona = agent._evogen_loader.load_persona(
        user_id=getattr(agent, "_user_id", agent.session_id),
    )
    
    # 3. 经验索引（基于当前 user_message 做语义检索）
    agent._evogen_experiences = agent._evogen_loader.load_experiences(
        query=user_message,
        user_id=getattr(agent, "_user_id", agent.session_id),
        top_k=5,
    )
# ── EvoGen 注入点 A 结束 ───────────────────────────────────────
```

### 3.2 注入方案

在 `volatile_parts` 构建完成后（L278 之前），插入 EvoGen 三引擎的提示词块：

```python
# ── EvoGen: 注入点 B — 三引擎提示词注入 ───────────────────────
# 将 EvoGen 的记忆快照、人格、经验以结构化提示词块注入到 volatile tier
# 放在 timestamp_line 之前，确保排在 external memory provider 之后

_evogen_blocks: List[str] = []

# 1. 人格注入（volatile 段优先级最高，最先显示）
if getattr(agent, "_evogen_persona", None):
    persona = agent._evogen_persona
    _p_block = (
        "# EvoGen Persona\n"
        f"- Name: {persona.get('persona_name', 'Default')}\n"
        f"- Tone: {persona.get('tone', 'neutral')}\n"
        f"- Verbosity: {persona.get('verbosity', 'medium')}\n"
        f"- Style Directives: {persona.get('style_directives', '')}\n"
        f"- Constraints: {persona.get('constraints', '')}\n"
        "\nAdopt this persona in all responses. "
        "The persona takes precedence over system identity for interaction style."
    )
    _evogen_blocks.append(_p_block)

# 2. 记忆快照注入
if getattr(agent, "_evogen_memory_snapshot", None):
    mem = agent._evogen_memory_snapshot
    _m_block = (
        "# EvoGen Memory\n"
        + mem
        + "\n\n[EvoGen Memory above is authoritative. "
        "Cross-reference with Hermes memory tool entries.]"
    )
    _evogen_blocks.append(_m_block)

# 3. 经验索引注入
if getattr(agent, "_evogen_experiences", None):
    exp = agent._evogen_experiences
    _e_block = "# EvoGen Experience Index\n"
    for idx, ex in enumerate(exp, 1):
        _e_block += (
            f"{idx}. [{ex.get('category', 'general')}] "
            f"{ex.get('summary', '')[:200]}\n"
            f"   Relevance: {ex.get('score', 0):.2f} | "
            f"Date: {ex.get('timestamp', 'unknown')}\n"
        )
    _e_block += (
        "\nUse these experiences as reference for similar situations. "
        "Do NOT re-execute completed tasks — only apply relevant patterns."
    )
    _evogen_blocks.append(_e_block)

for _block in _evogen_blocks:
    if _block and _block.strip():
        volatile_parts.append(_block.strip())
# ── EvoGen 注入点 B 结束 ───────────────────────────────────────
```

### 3.3 关于 Prompt Cache 的考虑

EvoGen 的 volatile 注入块 **天然与 Hermes 的 prefix-cache 策略兼容**：

1. Hermes 的 volatile 段在每次会话首轮重建时更新，后续轮次从 session DB 中读取缓存版本
2. EvoGen 注入的 memory/persona/experience 内容在 volatile 段内，**跟随 Hermes 现有的缓存刷新机制**
3. 当 EvoGen 记忆更新时，只需调用 `invalidate_system_prompt()`（已有函数，L306-L314）迫使下一轮重建

### 3.4 影响范围

- **修改文件**：`agent/system_prompt.py`（约 60 行新增代码）
- **修改风险**：低。只在已有 `volatile_parts` 列表追加项目，不改变三段式结构

### 4.2 注入方案

在 `post_llm_call` 钩子之后（L3979 之后）插入 EvoGen 异步记忆提取逻辑：

```python
# ── EvoGen: 注入点 C — 异步记忆提取 + 轨迹记录 ───────────────
# 在 Agent Loop 完成后、返回结果前：
# 1. 异步触发 EvoGen Memory Engine 从本轮对话中提取新记忆
# 2. 将本轮对话轨迹记录到 EvoGen Experience Store
# 使用独立线程 + 低优先级，不阻塞主响应返回

if getattr(agent, "_evogen_enabled", False) and final_response and not interrupted:
    from evogen.extractor import EvoGenExtractor
    from evogen.trajectory import EvoGenTrajectory
    
    _turn_messages = list(messages)  # snapshot for async processing
    _session_id = agent.session_id
    _user_id = getattr(agent, "_user_id", agent.session_id)
    _model = agent.model
    _evogen_loader = getattr(agent, "_evogen_loader", None)
    
    def _evogen_post_turn_async():
        """后台线程：记忆提取 + 轨迹持久化"""
        try:
            extractor = EvoGenExtractor()
            
            # 1. 异步记忆提取
            extractor.extract_memories(
                messages=_turn_messages,
                session_id=_session_id,
                user_id=_user_id,
                model=_model,
            )
            
            # 2. 轨迹记录（用于经验引擎）
            trajectory = EvoGenTrajectory(
                session_id=_session_id,
                user_id=_user_id,
                model=_model,
                messages=_turn_messages,
                final_response=final_response,
                personality_snapshot=(
                    agent._evogen_persona if _evogen_loader else None
                ),
            )
            trajectory.save()
            
        except Exception as _e:
            logger.warning(
                "EvoGen post-turn async failed: %s (session=%s)",
                _e, _session_id,
            )
    
    # 使用 daemon 线程，不阻塞主响应
    import threading
    _t = threading.Thread(
        target=_evogen_post_turn_async,
        daemon=True,
        name=f"evogen-post-turn-{_session_id}",
    )
    _t.start()
# ── EvoGen 注入点 C 结束 ───────────────────────────────────────
```

## 五、Compaction 模块改造方案（支持 memory_anchors 参数）

### 5.1 问题分析

当 Hermes 触发上下文压缩（ContextCompressor.compress()）时：

1. 中段对话被总结为结构化摘要
2. 系统提示词中的 **memory block 可能被压缩覆盖或削弱**
3. EvoGen 注入到 volatile 段的记忆/人格/经验信息在压缩后的 session rebuild 中可能丢失

**需要改造**：向压缩器传递 `memory_anchors` 参数，确保关键记忆锚点在压缩后的摘要中被显式保留。

### 5.2 改造方案

#### Step 1：扩展 `ContextEngine.compress()` 抽象签名

**文件**：`agent/context_engine.py`，第 81-101 行

## 六、Gateway 消息路由中的注入

### 6.1 Gateway 调用链分析

```
gateway/run.py:_handle_message()               L6420  ← 平台适配器消息入口
  ├─ 授权检查
  ├─ 命令拦截 (/new, /reset, /help...)
  ├─ 上下文构建 (build_session_context)
  └─ _handle_message_with_agent()              L7824  ← session + history 准备
       ├─ 会话卫生（自动压缩超大历史）
       ├─ 上下文提示词构建
       └─ _run_agent()                         L15397 ← AIAgent 构造 + 线程池调用
            └─ agent.run_conversation()        ← 最终调用
```

### 6.2 Gateway 注入策略

**Gateway 层面不需要额外改动**。原因：

1. `run_conversation()` 是 EvoGen 注入的最终入点。Gateway 通过 `_run_agent()` 调用 `agent.run_conversation()`，所有 EvoGen 逻辑在 Agent Loop 内部生效
2. Gateway 的会话卫生（session hygiene，L8024-L8340）使用独立的临时 `AIAgent` 实例，不应触发 EvoGen 逻辑 — 可通过 `skip_memory=True` 标志判断是否跳过 EvoGen 加载
3. Gateway 的 `_evict_cached_agent()` 机制确保跨轮次的 EvoGen 状态被正确刷新

### 6.3 建议：在 AIAgent 构造时添加 evogen_enabled 参数

**文件**：`run_agent.py`，`AIAgent.__init__()`

```python
# 在 __init__ 参数中添加
evogen_enabled: bool = False,
evogen_config: dict = None,
```

该参数通过 Gateway 的 `_run_agent()` 在构造 `AIAgent` 时从 config.yaml 读取并传递。

## 八、架构决策记录

### 8.1 为什么不使用 Monkey-Patch

1. Hermes 的 Agent Loop 在 `conversation_loop.py` 中是独立函数，通过 `_ra()` 延迟引用 `run_agent` 模块中的可 patch 符号。但这个机制是为测试设计的，不适合生产级注入
2. `system_prompt.py` 中的 `build_system_prompt_parts()` 是纯函数，无钩子设计
3. `ContextCompressor` 继承 `ContextEngine` 抽象类，修改抽象类后所有插件引擎自动受益
4. **结论：直接修改源码是唯一正确的选择**

### 8.2 Prompt Cache 兼容性

| 注入点 | 对缓存的影响 | 缓解措施 |
|--------|------------|----------|
| B（volatile 段注入） | volatile 段随 session 首轮重建而变化 | 遵循 Hermes 现有缓存策略 — session DB 持久化 system_prompt |
| memory_anchors | 压缩后重建 system_prompt 和压缩消息列表 | 压缩本身已触发缓存失效，anchors 不增加额外失效 |

### 8.3 错误隔离

- 所有 EvoGen 代码包裹在 `if getattr(agent, "_evogen_enabled", False)` 守卫中
- 注入点 C 的异步线程使用 daemon 模式，失败不影响主响应
- `memory_anchors` 为可选参数，不影响非 EvoGen 会话
